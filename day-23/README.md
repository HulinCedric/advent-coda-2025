# [Jour 23 - Se rendre indispensable !!!](https://coda-school.github.io/advent-2025/?day=23)

C’est la **veille de Noël**.

Tu as codé, testé, refactoré, documenté, aidé les elfes, ...

Bref : tu es devenu·e un·e pilier du Pôle Nord Tech Department.

Mais un doute t’envahit…  
Et si le Père Noël **ne faisait pas appel à toi l’année prochaine** ? 😱

Pas question de redevenir simple spectateur des fêtes !

Alors tu décides d’appliquer une technique redoutable pour **te rendre indispensable** : le [Crappy Driven Development](https://github.com/ythirion/crappy-driven-development).

## Contexte

Les elfes sont ravis : tous les tests sont verts, la livraison est prête.

Mais toi, tu sais que *trop de perfection, c’est dangereux* : quelqu’un pourrait te remplacer.  
Heureusement, tu connais une technique ancestrale transmise de génération en génération de développeurs malicieux…

> CDD : transformer un code simple et clair en un **chef-d’œuvre d’incompréhension**, sans casser un seul test.

## Ta mission

- **Télécharge le code du module de livraison des jouets.** (Le plus critique du Pôle Nord, évidemment.)
- Vérifie que **tous les tests passent** → c’est ta ligne de vie : tu devras les garder **verts** en permanence.
- **Refactoring** : trouve un refactoring qui rend le code moins lisible.
- **Implémente le refactoring** : applique le refactoring et modifie le code.
- **Vérifie que les tests passent** : exécute les tests pour t'assurer que le code fonctionne toujours après le refactoring.
- **Répète.** Encore. Et encore. Jusqu’à ce que le code soit **incompréhensible** même pour toi.
